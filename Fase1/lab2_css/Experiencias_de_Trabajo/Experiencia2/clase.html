Uso de selectores por clase

Esta copia del documento utiliza clases reutilizables para seleccionar y configurar grupos de elementos. Una misma clase puede asignarse a varios componentes que comparten la misma función visual.

Objetivo de la evidencia

Demostrar selectores como .seccion, .tarjeta, .texto, .enlace-nav y .lista. Las reglas de clase permiten reutilizar estilos sin depender del nombre de la etiqueta.

¿Cómo trabajan las APIs?

Existen diferentes tecnologías y arquitecturas para implementar APIs. En esta página se presentan REST, GraphQL, gRPC y SOAP como contexto para reutilizar clases sobre varios artículos.

[ REST ] Representational State Transfer

  • Arquitectura orientada a recursos identificados mediante URLs.
  • Utiliza métodos HTTP como GET, POST, PUT, PATCH y DELETE.
  • Es común trabajar con representaciones JSON para intercambiar información.

[ GraphQL ] Lenguaje de consulta para APIs

  • Permite que el cliente solicite los campos que necesita.
  • Trabaja habitualmente sobre un endpoint para consultas y mutaciones.
  • Su esquema describe tipos y operaciones disponibles.

[ gRPC ] Remote Procedure Call

  • Permite invocar operaciones remotas mediante contratos definidos.
  • Puede utilizar Protocol Buffers para describir mensajes y servicios.
  • Es común en comunicaciones entre servicios y sistemas distribuidos.

[ SOAP ] Simple Object Access Protocol

  • Protocolo de mensajería basado en XML.
  • La estructura de los mensajes utiliza elementos como Envelope, Header y Body.
  • Se encuentra en integraciones empresariales y servicios con contratos formales.

OWASP API Security Top 10 - 2023

Los siguientes riesgos organizan problemas relacionados con autorización, autenticación, consumo de recursos, lógica de negocio, configuración y administración de APIs.

API1:2023 // Broken Object Level Authorization - BOLA

Aparece cuando una API trabaja con identificadores de objetos pero no verifica correctamente si el usuario autenticado tiene autorización para acceder al recurso.

Observación: Ejemplo académico: modificar el ID de un objeto en una petición permite comprobar si el servidor valida correctamente la autorización.

API2:2023 // Broken Authentication

Ocurre cuando los mecanismos utilizados para identificar a los usuarios presentan fallas que pueden comprometer credenciales, tokens o mecanismos de autenticación.

Observación: Aspectos a revisar: protección de credenciales, control de intentos, manejo de sesiones y tratamiento seguro de tokens.

API3:2023 // Broken Object Property Level Authorization

Se relaciona con una validación incorrecta de las propiedades de los objetos que una API permite leer o modificar.

Observación: Puede provocar exposición excesiva de información o permitir cambios sobre propiedades que deberían estar protegidas.

API4:2023 // Unrestricted Resource Consumption

Las peticiones a una API consumen CPU, memoria, almacenamiento y ancho de banda; si no existen límites adecuados, los recursos pueden agotarse.

Observación: Controles relacionados: límites de tamaño, paginación controlada y restricciones sobre el consumo de recursos.

API5:2023 // Broken Function Level Authorization - BFLA

Aparece cuando una API no controla correctamente qué funciones puede ejecutar cada rol o tipo de usuario.

Observación: Ejemplo académico: verificar que una cuenta regular no pueda ejecutar funciones reservadas para administración.

API6:2023 // Unrestricted Access to Sensitive Business Flows

Se produce cuando funcionalidades importantes para el negocio pueden utilizarse de manera automatizada y abusiva sin suficientes controles.

Observación: Los flujos sensibles necesitan controles que reduzcan automatización abusiva y uso repetitivo no previsto.

API7:2023 // Server-Side Request Forgery - SSRF

Ocurre cuando una API obtiene un recurso remoto utilizando una URI proporcionada por un usuario sin validarla correctamente.

Observación: Funciones como webhooks, carga por URL e integraciones externas requieren validación y restricciones apropiadas.

API8:2023 // Security Misconfiguration

Las configuraciones incorrectas en servidores, frameworks o servicios que soportan una API pueden exponer información o aumentar la superficie de ataque.

Observación: Se deben revisar métodos innecesarios, mensajes de error, configuraciones de seguridad y servicios expuestos.

API9:2023 // Improper Inventory Management

Una organización puede mantener versiones antiguas, endpoints olvidados o APIs no documentadas que continúan accesibles.

Observación: Mantener un inventario actualizado ayuda a identificar versiones antiguas, servicios internos expuestos y endpoints de prueba.

API10:2023 // Unsafe Consumption of APIs

Ocurre cuando una aplicación confía excesivamente en información proveniente de APIs externas y procesa esos datos sin las validaciones necesarias.

Observación: Los datos recibidos desde servicios externos también deben tratarse como entradas que requieren validación.

Controles de seguridad

Los riesgos estudiados muestran la importancia de aplicar controles de autenticación, autorización, validación de entradas y limitaciones sobre los recursos utilizados por una API.

  1. Validar autorización antes de entregar o modificar recursos.
  2. Proteger credenciales, sesiones y tokens de autenticación.
  3. Aplicar límites al consumo de recursos.
  4. Validar la información recibida, incluso desde servicios externos.
  5. Mantener actualizado el inventario de APIs y versiones.
  6. Eliminar configuraciones y servicios innecesarios.

Registro de verificación

Se verificó en el navegador que una misma clase aplicada a diferentes elementos reutiliza la regla CSS correctamente. Se realizaron cambios en la clase .tarjeta y se confirmó que todas las tarjetas asociadas actualizaron su presentación.

Conclusión

Los selectores de clase ofrecen mayor flexibilidad que los selectores por nombre porque permiten agrupar elementos por función o apariencia. Son apropiados para estilos reutilizables y ayudan a reducir repetición, mantener consistencia y facilitar cambios globales.
